Executive Summary
SIH26189 (Ministry of Home Affairs, “AI-Powered Criminal Network Analysis System”) calls for an AI-enabled
investigation platform that ingests crime data, discovers hidden networks of suspects and events, and
provides analysts with an interactive graph-based interface for intelligence (people, phones, vehicles,
locations, transactions, etc.)【21†L10439-L10446】. The system must extract entities from varied sources
(FIRs, CDRs, financial records, reports, social-media, etc.), build relationship maps, identify key
influencers, detect suspicious patterns, and offer visual/analytic insights【21†L10439-L10446】. 
In practice, this means developing a web/mobile prototype with pipelines for (1) data ingestion (mock/
synthetic crime data), (2) NLP entity extraction (names, phone numbers, accounts, vehicles, locations,
organizations, etc.), (3) entity resolution (deduplicating identities), (4) graph construction (nodes/edges
for entities and relationships), (5) graph analytics (centrality, communities, pattern/anomaly detection),
and (6) an investigator dashboard (searchable interface, network graph visualization, alerts). For a 36–72-
hour hackathon, the MVP should focus on core features: data upload, basic NLP , simple graph builder , and
an interactive network graph with highlighting of top suspects. A full product (post-hackathon) could
expand on sources, sophisticated ML/LLM modules, advanced analytics and security. 
Below is a deep implementation plan covering objectives and constraints, prioritized features (MVP vs.
production), team roles, timeline (via Mermaid Gantt), architecture (Mermaid diagram), data schema
(relational + graph), API design, synthetic data strategy, NLP pipeline details, graph analytics methods, UI/
UX design (wireframes and user flows), security/privacy/ethics, deployment/CI, evaluation criteria, and risk
mitigation. The plan assumes a 4–6 member CSE team, ~2–3 day hackathon, cloud-neutral approach (e.g.
AWS/GCP/Github Actions). All recommended components are either open-source or easily accessible; no
real sensitive data should be used (only synthetic/mock data to respect privacy). 
Sources: Official SIH statement【21†L10439-L10446】; literature on criminal network analysis and
knowledge-graph approaches【26†L87-L96】【31†L127-L136】; graph analytics guides【31†L229-L238】.
These ground the design choices (e.g. knowledge graphs for multi-source integration【26†L87-L96】, rule-
based anomaly detection【31†L127-L136】, centrality for influencer detection【31†L229-L238】). 
1. SIH26189 Goals & Constraints
Objective (official): “Develop an AI-powered system that automatically analyzes structured and
unstructured crime-related data to uncover criminal networks, identify key influencers, detect
suspicious patterns, and provide actionable intelligence for investigators.”【21†L10439-L10446】.

Data Sources: Ingest multiple data sources: FIRs, police reports, CDRs (call detail records),
transaction logs, surveillance logs, social media intelligence, criminal databases, etc. (All synthetically

Entity Extraction: Extract entities from text and data: persons, locations, vehicles, phone numbers,
organizations, plus events and transactions【21†L10439-L10446】.

Table: Graph Nodes/Edges
Node (Label) Key Props Edge (Type) From Label - To Label
Person person_id, name HAS_PHONE Person → Phone
Phone number INVOLVED_IN Person → Case (if call evidence)
Account account_id CALLED Phone → Phone (call edge)
Vehicle plate_number TRANSFERRED_TO Account → Account (transaction edge)
Location location_id, name OWNS Person → Vehicle

Graph DB is flexible – no fixed schema required, but definining expected node/edge types clarifies queries.

5. Data Strategy
Since no real data is available, we generate synthetic datasets that mimic crime/investigation records. The
key is to create realistic multi-source data that exercises all features:
People: generate 50–200 fictional people with names, addresses. Assign random personal details.
Phones: assign each person 1–2 phone numbers.
Locations: generate 10–20 locations (cities, addresses, jail, police stations).
Vehicles: assign license plates to some people.
Cases/FIRs: create ~30 cases, each with:
a case ID, date, description text (fake police narrative).
involved people (some suspects, victims, officers).
events (e.g. "on date, Person A called Person B", "Person C transferred $X to Person D", etc. Include
these in logs).
Call Detail Records (CDR): ~200 entries: (caller, callee, timestamp, duration, 
towerLocation)
Transactions: ~200 transfers: (fromAccount, toAccount, amount, date)  including some
multi-hop chains.
Social media (optional): simple logs: "Person A posted about Person B", etc.
Associations: define a few groups or gangs. E.g. “Gang Alpha” with 3 leaders and 5 members. Some
persons have MEMBER_OF .
Criminal History DB: list some known associates or prior convictions (for flavor).

Synthetic Data Generation
Use Python or Google Sheets to create fake names (e.g. https://github.com/ianstormtaylor/english-
name-generator) and numeric IDs. 
Ensure connectivity: e.g. Person A calls Person B, Person B transfers money to Person C, etc.,

Include distractors (unrelated persons, calls) to test filtering.
Anonymization & Ethics
All data is synthetic. No real names. Use random or clearly fake identifiers.
If using any real phrases, ensure they contain no PII (these samples are not real people).
This demonstrates respect for privacy and avoids ethical pitfalls【26†L87-L96】.
Test Cases
Design a few scenarios to validate features:
Simple Connection: Person X -> Y via one phone call and one account transaction. 
Search X should show Y as connected (via Phone, Account).
Influencer Detection: Person A calls 5 others (hub). Should rank high by degree.
Suspicious Cycle: A→B ($100k) →C ($99k) →A (5k). System should flag cycle.
Community: Two separate gangs, weak links between. Community detection finds 2 clusters.
Timeline Filter: If time allows: filter calls/transactions within a date range.

Tools & Models

Vehicle plates: [A-Z]{2}\d{2}\s*[A-Z]{1,2}\s*\d{4}  (Indian format).

Two approaches:
Rule-Based (explainable): For example, flag if:
High volume: A node with very high transaction count or call volume (outlier degree)【31†L139-

Cycle Detection: Identify directed cycles in money flows (common money-laundering sign)

Rapid succession: Same account transfers large sum multiple times in short window. 
Isolated cluster: A small fully connected clique (money mule ring).

Example Pseudocode (Python):
def detect_cycles(G):
cycles = []
for node in G.nodes():
for neighbor in G.successors(node):
if G.has_edge(neighbor, node):
cycles.append((node, neighbor))
return cycles
For more complex, use networkx simple_cycles for directed graph of accounts.
Complexity: For hundreds of nodes, simple algorithms (O(N^2)) are fine. Mention that for large graphs, use
optimized libraries.
